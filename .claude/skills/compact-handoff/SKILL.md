# Свёртка сессии

Пользователь сейчас сожмёт контекст или закроет сессию. **После этого исчезнут все выводы
инструментов**: id, версии, ссылки, номера — останется только пересказ. Всё, что должно пережить
этот момент, обязано лежать в файле, а не в переписке.

Порядок ниже — от самого дорогого к потерям до самого дешёвого. Пройти целиком, даже если
кажется, что сессия была пустой: «ничего не делали» — тоже вывод, и его достаточно записать одной
строкой.

## 1. Незакоммиченная работа (теряется первой)

Репозитории вложенные и **независимые** — статус из корня покажет только хаб:

```bash
for d in . wh11ed wh11ed-api wh40k-appdata wh-glossary; do
  [ -d "$d/.git" ] && { echo "=== $d"; git -C "$d" status --porcelain; }
done
```

Для каждого грязного дерева: либо закоммитить (осмысленным сообщением, не «wip»), либо **сказать
пользователю явно**, что осталось несохранённым и почему. Молча оставлять нельзя.

**Пушить только если пользователь просил.** Незапушенные коммиты — это нормально, но их надо
перечислить: после компакта о них никто не вспомнит.

## 2. Журналы (`journal/`, скил `journal`)

- **Активный журнал дописать**: что сделано за сессию, какие решения приняты и почему, **где
  именно остановились и что следующий шаг**. Последнее — самое важное: с него начнётся
  следующая сессия.
- Задача закрыта → шапка `Итог:` одной строкой, `git mv` в `archive/YYYY/`, строка в `INDEX.md`.
- Упёрлись в чужое решение, дату или ответ → `paused/` с полем **`Ждём:` — чего именно и от
  кого**.
- Работа шла без журнала, но переживёт сессию → завести журнал сейчас.
- Поправить `INDEX.md`, если что-то двигалось.

## 3. Память (`~/.claude/projects/…/memory/`)

- Записать то, что **не выводится из кода и не является журналом**: решения пользователя,
  предпочтения, нестыковки инструментов, внешние идентификаторы.
- **Проверить существующие файлы на устаревание.** Самая частая ложь — статус: «в работе» после
  выката, «ждём» после ответа, «отложено» после закрытия. Такой файл хуже отсутствующего.
- Неверное — удалить, а не дописать оговорку.
- Каждая новая запись = файл + строка в `MEMORY.md`. Перед записью **проверить факт**, а не
  зафиксировать правдоподобное.
- Не дублировать то, что уже есть в репозитории или в журнале — там оно живёт точнее.

## 4. Хвосты, которых нет ни в коде, ни в журнале

Пройтись по списку и записать в журнал всё, что откликнулось:

- **Что задеплоено, а что нет.** Назвать версию в проде и перечислить коммиты, которые в неё не
  попали. Разъехавшееся представление о проде — самая дорогая потеря контекста.
- **Фоновые команды**: закончились? Если что-то ещё крутится — дождаться или записать, что
  запущено и где лог.
- **Внешние ожидания**: ответ человека, проверка DNS, модерация, чужой деплой.
- **Файлы в scratchpad**, которые нужны дальше: он сессионный и не переживёт. Нужное — перенести
  в репозиторий или пересказать в журнале.
- **Сырые данные из выводов инструментов**, на которые мы будем ссылаться: id секретов, версии
  функций, токены ресурсов, точные числа проверок.

## 5. Короткое резюме пользователю

Три блока, без воды:

- **Сделано** — по пунктам, с номерами версий и коммитов.
- **Осталось несохранённым / незапушенным** — если пусто, так и сказать.
- **Чем продолжить** — одна-две строки, чтобы следующая сессия стартовала без раскопок.

Не описывать сам процесс свёртки — только результат.
