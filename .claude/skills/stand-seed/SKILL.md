# Сид стенда: ростеры и партии

Владелец смотрит руками и хочет, чтобы всё **уже лежало** в его браузере: ростеры в конструкторе,
партии в истории трекера, каждая открывается через «Продолжить игру». Для этого в `wh11ed` есть
страница-сид. Ссылки на отдельные ростеры — это скил `roster-links`; этот — когда нужен набор.

## Откуда что берётся

- `scripts/lib/test-rosters.mjs` — девять ростеров-спецификаций (юниты по id, оружие по подписи).
- `scripts/lib/test-games.mjs` — партии-спецификации: армии (фракция или ключ тестового ростера),
  опции трекера, момент `upTo: [раунд, ход, фаза]` или `null` (не начата). Партию **играет
  настоящий стор** до этого момента — счёт по раундам, CP из журнала, сброшенные карты — и
  убирает в историю как прерванную.
- `npm run stand:seed` пишет `public/_seed.json` + `public/_seed.html` (оба в `.gitignore`).
- `scripts/lib/test-games.test.js` держит каждую партию там, где она задумана, — гоняется в `npm test`.

Таблица наборов — `RELEASE-CHECKLIST.md`, разделы «Набор тестовых ростеров» и «…партий».

## 1. Стенд

Сид собирается **из той копии, чей стенд смотрит владелец** (main — `wh11ed`, ветка — её worktree):
данные и форма партии у них разные. Проверить, что на порту живой Vite именно оттуда:

```bash
lsof -iTCP:5175 -sTCP:LISTEN -P      # и pwd процесса, если сомневаешься
```

Нужен вход («тест-вход» в ⚙) — бэкенд стенда (`npm run stand` в `wh11ed-api`, порт 8787).
Облако партий и ростеров в dev замокано, по-настоящему туда ходит только `/party`.

## 2. Сценарии под задачу

Готовых наборов хватает для общего прохода. Под конкретную проверку — **дописать спецификацию**, а
не собирать руками в браузере: новая партия — строка в `TEST_GAMES`, новый ростер — в
`TEST_ROSTERS` (и строка в таблице чек-листа). Подбирать варианты по осям, которые меняют экран:
ростер у обоих / у одного / ни у кого; фазы вкл / выкл; тактические / фиксированные вторичные;
singles / doubles; не начата / середина / последний ход; твист, режим BP, без фракций, ошибки
в ростере. Рядом с особым случаем держать контрольный.

```bash
cd <копия> && npm run stand:seed && npx vitest run scripts/lib/test-games.test.js
```

## 3. Загрузить

**Владелец открывает сам** `http://localhost:<порт>/_seed.html` — в **своём** браузере (у него
Яндекс Браузер; хранилище своё у каждого браузера и каждого порта, поэтому засеять «за него» из
Chrome-расширения или playwright нельзя — 2026-10-04 на этом споткнулись). Страница:

- добавляет ростеры (id `test-…`) и партии (id `seed-…`) к его собственным, их не трогает;
- повторный заход заменяет только засеянное — так доигранную партию возвращают в исходное;
- если ростеры в браузере в другой схеме, отказывается и просит сначала открыть приложение.

## 4. Прежде чем отдать — проверить самому

Playwright (системный Chrome, `reference_playwright_screens` в памяти): открыть `/_seed.html`,
дождаться `/ru/tracker`, открыть пару партий → «Продолжить игру» → скриншот. Убедиться, что
экран показывает то, ради чего партия заведена (кнопка «Начать игру», «Завершить игру» на последнем
ходу, ростер на вкладке). История показывает по 10 — одиннадцатая за «Показать ещё».

## 5. Как отдавать

Ссылку на `/_seed.html` и таблицу «Партия N — что смотреть — где остановлена». В конце одна
строка: стенд какой копии, порт, ветка.
