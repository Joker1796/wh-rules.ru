# Разбор жалоб игроков

## 1. Прочитать очередь

```bash
cd wh11ed-api
export YDB_ENDPOINT=ydb.serverless.yandexcloud.net:2135
export YDB_DATABASE=/ru-central1/b1gp4gkufb7h5t4bgd41/etnj9vg2so92cj89voa7
export YDB_ACCESS_TOKEN=$(~/yandex-cloud/bin/yc iam create-token)   # yc не в PATH шелла
npm run feedback:list                 # дайджест, свежие сверху
npm run feedback:list -- <id-префикс> # один отчёт целиком: контекст, ошибки, вложение
npm run users:count                   # сколько аккаунтов всего и по месяцам (тот же env)
```

В отчёте есть версия приложения, маршрут, последние JS-ошибки и — если игрок отметил галочку —
партия или ростер. Контакта у отправителя нет: ответ уходит не письмом, а правкой и записью в
чейнджлоге.

## 2. Проверить, а не поверить

**Каждая жалоба проверяется по первоисточнику до вердикта.** История показала оба направления
ошибки: и «это не баг» на настоящем баге, и «appdata врёт» там, где врали мы.

- Правила и датащиты — `wh40k-appdata` (ветка `master`), очки — MFM.
- Считать арифметику руками, а не сверять формулировки.
- Не нашёл подтверждения — так и сказать («не воспроизводится, нужны детали»), а не додумывать.
- Игрок может помнить 10-ю редакцию; это тоже вердикт, но только после проверки.

## 3. Развести на три кучи

- **Наш баг** → правка + гейт, который поймал бы это раньше. Если гейта нет — завести: каждый
  существующий гейт появился потому, что баг первым нашёл игрок.
- **Не баг** → записать почему, чтобы второй раз не разбирать заново.
- **Отдельная задача** → журнал в `journal/paused/` хаба с описанием, а не строчка в конце
  чужого документа: там она потеряется.

## 4. Закрыть

Правки → скил `data-gates` → запись в `changelog.js` → релиз (скил `release-frontend`).
Если из разбора родился переиспользуемый приём — в `wh11ed/APPDATA-SYNC-LESSONS.md`.

Смоук-записи, оставленные при проверке самой формы, из базы удалять — иначе они мешают читать
настоящую очередь.
