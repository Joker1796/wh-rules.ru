# Журналы задач

Система описана в `journal/README.md`; здесь — операции.

## Посмотреть, что в работе

Читать `journal/INDEX.md` — по строке на журнал. Полный текст открывать только по нужному.

## Завести новый

Файл `journal/active/YYYY-MM-DD-slug.md`, дата — сегодняшняя, `slug` — латиницей, коротко.
Шапка — блок цитаты:

```markdown
> **Статус:** активен
> **Репозитории:** wh11ed
> **Начато:** 2026-09-13
> **Связано:** [другой журнал](../paused/….md)
```

Дальше — что делаем, почему именно так, и что решили по спорным местам. Журнал пишется **для себя
через полгода**: решения и причины важнее списка сделанного. Добавить строку в `INDEX.md`.

Заводить журнал стоит на всё, что переживает одну сессию: крупную фичу, курс работ, разбор,
который упрётся в чужое решение. Мелкая правка журнала не требует.

## Перевести в другой статус

**`git mv`, а не правка строчки** — тогда статус виден в истории:

```bash
git mv journal/active/2026-08-26-seo.md journal/paused/
```

Затем поправить в шапке `Статус:` (и добавить `Ждём:` для paused — **чего именно и от кого**;
или `Итог:` для архива — одной строкой, что осталось в проде), передвинуть строку в `INDEX.md`.
Архив раскладывается по годам: `journal/archive/2026/`.

## Закрыть

Итог не влезает в строку — значит задача закрыта не до конца. Открытые хвосты не дописываются в
конец закрываемого файла: они уезжают **отдельным журналом** в `paused/`, иначе их никто не
найдёт. Переиспользуемая процедура, родившаяся из задачи, уезжает в скил или в `CLAUDE.md` рядом
с кодом — журнал на неё ссылается.

## Чего в журнале не должно быть

- Таблиц и списков, которые можно сгенерировать или сгрепать из репозитория — только ссылка,
  где их взять.
- Описания того, как устроен код: это `CLAUDE.md` соответствующего репозитория.
- Секретов и ключей: хаб публичный.
