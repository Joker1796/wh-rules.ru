# Обновление базы правил

Полная процедура — `wh11ed/DATA-SYNC.md` (это единая точка входа, читать её целиком при первом
заходе). Здесь — каркас и то, на чём спотыкаются.

**Источник правды по правилам — `wh40k-appdata`**, дамп официального приложения GW. MFM вторичен
и важнее appdata только по UNIQUE-тегам детачментов. При неоднозначности **спросить пользователя**,
а не гуглить и не качать PDF. Ровно два исключения, где appdata пуст и PDF/APK — единственный
источник: **картинки раскладок** (только ресурсы APK) и **FAQ колоды Chapter Approved**
(только PDF компаньона) — см. шаг 1b. Ветки разные: appdata на `master`, wh11ed на `main`.

## 1. Ingest

Положить `.xapk`/`.apk` в `sources/apk/`, затем:

```bash
cd ../wh40k-appdata && node scripts/ingest.mjs        # сам найдёт свежий пакет; печатает old→new data_version
node scripts/changes.mjs --json changes.json          # классифицированный дифф по стабильным id
```

## 1b. Картинки раскладок и PDF компаньонов — у них свой канал

Часть Event Companion живёт **вне appdata**, поэтому обычный `npm run sync` её не видит:

```bash
cd ../wh11ed
npm run layouts            # 45 диаграмм раскладок против артворка в свежем APK
node scripts/extract-layout-images.mjs   # если гейт назвал перерисованные — вытащит и переименует их
npm run images:webp && npm run images:dims && npm run imghash -- --write
npm run companions         # версии четырёх PDF + FAQ колоды, которого в appdata нет вовсе
```

Компаньоны качать в `sources/` с warhammer-community.com (раздел Downloads → Event Companions) —
это **исключение** из правила «не качать PDF»: у appdata нет ни картинок раскладок, ни FAQ.
Когда `npm run companions` показывает бамп версии, он печатает GW-шный WHAT'S NEW: прочитать,
внести, потом `npm run companions -- --write`.

## 2. Сначала план, потом правки

Классифицировать дифф **до** редактирования. Обычно подавляющее большинство строк «prose changed» —
это нормализация разметки, а не изменение правила; такая классификация экономит целый проход.
Известные ложные срабатывания перечислены в `DATA-SYNC.md` §3 и `APPDATA-SYNC-LESSONS.md` — прежде
чем чинить находку, проверить, не описан ли её класс там.

## 3. EN-проход

Правки в `wh11ed/src/data/**`, сверка через `npm run sync` (+ `sync:text`, `sync:mfm`).
Числа очков берутся из MFM, а не из appdata.

## 4. RU-проход — отдельно

```bash
npm run translate:queue     # читает ../wh40k-appdata/changes.json
npm run roster:texts-ru     # RU-тексты вооружения генерируются из EN, в очередь не идут
npm run faq                 # после него выровнять индексный оверлей factionFaqRu.json
```

Правила перевода — скил `ru-translate` в репозитории wh11ed.

## 5. Гейты и закрытие

Скил `data-gates` (полный прогон). Чек-лист конца итерации — `DATA-SYNC.md` §6: перегенерировать
индексы (`datasheets:index`, `faction-rules:index`, `phases:index`, `sourceids`, `condkeywords`),
проверить `--check`-генераторы, записать новые уроки в `APPDATA-SYNC-LESSONS.md`, добавить запись
в `changelog.js` и выкатить (скил `release-frontend`).

## Что помнить

- **Перепроверяй, не утверждай.** Прежде чем назвать что-то «подтверждённым не-багом» или
  «нестыковкой appdata», проверить арифметикой или первоисточником.
- **«MFM молчит» ≠ «MFM снял»** — отсутствие строки в MFM не отменяет правило.
- Бандлы иногда теряют данные: плоский экспорт `factions/<slug>.json` беднее реляционных
  `tables/*.json`; при сомнении читать таблицы.
- Журнал крупного захода (новый кодекс, большой бамп) заводить в `journal/active/` хаба.
