# Ростеры ссылкой

Владелец проверяет руками и **хочет ссылку**, а не текст для импорта и не инструкцию «создайте
лист». Ссылка — та же, что делает кнопка «Поделиться» в конструкторе:
`/roster/shared#r=<payload>`. Ростер едет в хэше URL, на сервер ничего не уходит. Открыл →
«Сохранить к себе» → лист у него в конструкторе.

## 1. Стенд

Ссылки по умолчанию ведут на локальный стенд `http://localhost:5173`, поэтому сначала убедиться,
что там живой Vite **из `wh11ed` на ветке с проверяемой правкой**:

```bash
lsof -iTCP:5173 -sTCP:LISTEN -P          # что-то уже слушает? чьё оно (worktree или main)?
cd wh11ed && npx vite --port 5173 --strictPort    # фоном (run_in_background)
```

Бэкенд (`npm run stand` в `wh11ed-api`, порт 8787) для ростеров не нужен — только если проверка
про облако/вход. Ссылки на прод (`--base https://wh-rules.ru`) — только если владелец попросил
проверить выкаченное.

## 2. Списки — текстом в формате экспорта GW

Писать в scratchpad, по файлу на ростер. **Строки вооружения не писать** — без них отряд берёт
снаряжение по умолчанию, и импорт не спотыкается о названия оружия (с ними легко промахнуться:
«Astartes chainsword» в данных называется «Chainsword»). Писать снаряжение, только если проверка
про него — и сверять имена с `src/data/roster/<slug>.js`.

```
Проверка: что именно смотрим (1000 points)

Space Marines
Incursion (1000 points)
Gladius Task Force (2 Detachment Points)

Attached Units
Attached Unit 1

Chaplain (60 points)
• Attached as: Leader (Character)
• Warlord

Ancient (40 points)
• Attached as: Support (Character)

Intercessor Squad (85 points)
• Attached as: Bodyguard (Battleline)

OTHER DATASHEETS

Intercessor Squad (85 points)
```

- **Название листа = что проверять**: «Проверка: капеллан и Ancient в одном отряде». Владелец
  видит его в списке листов.
- Кто к кому может прикрепиться — поле `leads` юнита в `src/data/roster/<slug>.js`; детачменты —
  `detachments` там же. Не угадывать по памяти.
- Рядом с изменённым случаем класть **контрольный**: тот же отряд без лидера, тот же лидер один.
  Разница видна только при сравнении.
- Очки в тексте не важны — конструктор пересчитает по своим данным.

Настоящие турнирные списки — `python3 scripts/fetch-listhammer.py --all <файл>` (аргумент —
путь, без `--corpus`). Но они экспортированы против своей версии данных: после нового кодекса
старые названия оружия не импортируются. Свои списки надёжнее.

## 3. Ссылки

```bash
cd wh11ed && npx vite-node scripts/roster-link.mjs <scratchpad>/*.txt          # → localhost:5173/ru/…
npx vite-node scripts/roster-link.mjs list.txt --base https://wh-rules.ru --en  # прод, EN
```

Скрипт гонит текст через тот же импорт, что окно «Импорт». Строка `✗` значит, что список
импортировался бы не так, как написан (нет датащита, детачмента, неразмещённое оружие), —
**такую ссылку не отдавать**, а исправить текст.

## 4. Прежде чем отдать — открыть самому

Хотя бы одну ссылку открыть в playwright (скил-независимо: `reference_playwright_screens` в
памяти): «Сохранить к себе» → `/view` → карточка нужного юнита → убедиться, что проверяемое
действительно видно. Отдавать ссылку, по которой владелец увидит не то, — хуже, чем не отдать.

## 5. Как отдавать

Каждый ростер — одной строкой: **markdown-ссылка с понятным именем** + что на нём смотреть.
Длинный payload голым URL в чат не вываливать.

```
- [SM: капеллан и Ancient](http://localhost:5173/ru/roster/shared#r=…) — Отряд 3: у Intercessors
  и у Chaplain OC 3/2, у Ancient [LANCE]; Battleline-Intercessors без лидера — контроль, OC 2.
```

В конце — одна строка, что стенд поднят и где (порт, ветка).
