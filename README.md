# wh11ed

Двуязычный (EN/RU) справочник по правилам **Warhammer 40,000, 11-я редакция** — основные правила,
Event Companion, фракции (правила армий, детачменты и листы данных юнитов) — плюс офлайн-трекер
партии. Работает как обычный сайт и ставится как PWA — установленное приложение после
однократного прогрева работает полностью офлайн, за столом и без сети.

🌐 **[wh11ed.ru](https://wh11ed.ru)** · переезжает на **wh-rules.ru**

**Проект открытый, под лицензией [MIT](LICENSE). Контрибьюторам рады** — как коду, так и
правкам правил и перевода. Как включиться — ниже.

---

## Это зонтичный репозиторий

**Здесь нет кода.** Репозиторий хранит только оболочку рабочей области: документацию о том,
из чего состоит проект и как его собрать. Сам продукт живёт в отдельных репозиториях, которые
клонируются **внутрь этой папки** и намеренно занесены в `.gitignore` — вложенными
репозиториями или сабмодулями они не являются.

Так сделано сознательно: проекты деплоятся и версионируются независимо (фронт — статикой в
бакет, бэк — облачной функцией), а словарь вообще никем не импортируется. Сабмодули связали бы
их версии друг с другом без всякой пользы.

| Папка | Что это | Стек | Репозиторий |
|-------|---------|------|-------------|
| `wh11ed/` | **Фронтенд** — Vue 3 SPA: правила, Event Companion, фракции, трекер партии, PWA. Здесь ~99% работы | Vue 3, Vite, Vitest | [wh11ed](https://github.com/Joker1796/wh11ed) · MIT |
| `wh11ed-api/` | **Бэкенд** — микросервис облачного бэкапа истории трекера. Нужен только для входа и синхронизации; без него всё остальное работает | TypeScript, Hono, YDB, Yandex Cloud Functions | [wh11ed-api](https://github.com/Joker1796/wh11ed-api) · MIT |
| `wh-glossary/` | **Справочник** перевода сообщества (34k пар EN→RU). Не библиотека, никем не импортируется | TSV + Python | приватный — см. ниже |
| `sources/` | Исходники: PDF правил, кодексы, глоссарии. Папка под гитом, содержимое — нет | — | — |

## Сборка рабочей области

```bash
git clone https://github.com/Joker1796/wh-rules.ru.git 11 && cd 11

git clone https://github.com/Joker1796/wh11ed.git
git clone https://github.com/Joker1796/wh11ed-api.git      # только если трогаешь синхронизацию

cd wh11ed && npm install && npm run dev                    # http://localhost:5173
```

Этого достаточно: **фронт собирается и запускается без бэкенда, без словаря и без
исходников.** Правила, трекер и PWA — всё клиентское. Недоступны будут только вход и
облачный бэкап истории: по умолчанию фронт смотрит на локальный API
(`VITE_API_BASE_URL`, по умолчанию `http://localhost:8787`), так что без запущенного
`wh11ed-api` попытка входа просто не пройдёт. Чтобы посмотреть UI залогиненного
пользователя без настоящего OAuth, в dev-сборке есть мок (`useAuth.js`, флаг
`wh11ed-dev-mock-auth`; в прод-сборку Vite его не включает).

`sources/` нужна только для повторного извлечения текстов и картинок — см.
[`sources/README.md`](sources/README.md).

```bash
cd wh11ed
npm run dev      # дев-сервер
npm test         # Vitest
npm run build    # прод-сборка в dist/
```

## Что открыто, а что нет

Открыты **`wh11ed` и `wh11ed-api`** — оба под MIT, оба принимают PR.

**`wh-glossary` — приватный.** Это машинная выжимка из чужого документа: глоссария, который
годами собирало русскоязычное сообщество переводчиков. Выкладывать его в общий доступ без
согласия авторов мы не будем; вопрос об открытии открыт до получения апрува. Ни фронт, ни бэк
от него не зависят — это справочник для работы над переводом, а не часть сборки, так что его
отсутствие ничего не ломает.

Отдельно: тексты правил Warhammer 40,000 принадлежат Games Workshop. MIT покрывает **код**
этого проекта, а не игровые тексты и не содержимое `sources/`.

## Куда смотреть под задачу

- **Правила, тексты, переводы EN/RU, вёрстка** → `wh11ed/src/data/`, `wh11ed/src/views/`.
  Первым делом прочитать `wh11ed/CLAUDE.md` — там про пайплайн data→view и двуязычные конвенции.
- **Трекер партии, очки, миссии, стратагемы** → `wh11ed/src/composables/useTracker.js` +
  `wh11ed/src/components/tracker/`.
- **PWA, офлайн, деплой фронта** → разделы PWA / Deployment в `wh11ed/CLAUDE.md`.
- **Логин, облачный бэкап, серверные ошибки** → `wh11ed-api/` (HTTP-контракт — в его `README.md`).
- **Не уверен, фронт это или бэк** → почти всегда фронт.

Каждый подпроект несёт свой `CLAUDE.md` с подробностями; в этой папке
[`CLAUDE.md`](CLAUDE.md) — только маршрутизация и стиль работы.

## Связи между проектами

- `wh11ed` ↔ `wh11ed-api` связаны **контрактом**: `domain/game.ts` на бэке валидирует конверт
  сохранённой партии. Меняя формат партии или auth-флоу на фронте — проверь бэк, и наоборот.
  Это единственное место реальной сцепки.
- `wh-glossary` ни с чем не связан кодом.

## Как включиться

Проект держится на двух вещах, и помочь можно с любой:

- **Данные и перевод.** Основная масса и основной риск — двуязычные data-файлы правил.
  Самые частые баги здесь не логические, а рассинхрон EN↔RU. Правки текстов, переводов и
  глоссов приветствуются; конвенции описаны в `wh11ed/CLAUDE.md` (раздел Bilingual content).
- **Код.** Фронт несёт много «скрытой» инфраструктуры (PWA, офлайн-прогрев, resume-view,
  кэш-стратегии) — её легко сломать незаметно, поэтому в `CLAUDE.md` подпроектов
  задокументированы инварианты «не чини это». Перед оптимизацией стоит проверить, нет ли на
  неё явного запрета.

Практически: форкни нужный репозиторий, заведи ветку, прогони `npm test` и `npm run build`,
открой PR. Линтера нет; следуй стилю окружающего кода. Вопросы и предложения — через issues.
