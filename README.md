# WH Rules

Двуязычное (EN/RU) приложение для игры в **Warhammer 40,000, 11-я редакция**. В нём можно найти
правило, собрать ростер и отыграть партию. Правила твоего списка в партии применяются к юнитам
прямо на экране. Играть можно на одном телефоне или вместе на нескольких.

Начиналось всё как поиск по правилам вместо листания PDF за столом. Справочник и сейчас основа,
а конструктор и трекер выросли поверх. Это обычный сайт, который ставится как PWA. Установленное
приложение после однократной загрузки работает без сети. **Аккаунт ни для чего не нужен.** Вход
даёт только синхронизацию между устройствами и роль хоста в совместной партии.

🌐 **[wh-rules.ru](https://wh-rules.ru)**

> Раньше сайт жил на `wh11ed.ru`. С 26 августа 2026 года тот домен заморожен и отдаёт 301 сюда.

**Проект открытый, под лицензией [MIT](LICENSE).** Контрибьюторам рады: и с кодом, и с правками
правил и перевода. Как включиться — ниже.

## Что умеет

- **Правила.** Core Rules, Event Companion (миссии, 45 раскладок, Doubles, FAQ), все 30 фракций с
  детачментами, стратагемами и датащитами, включая Legends. Ещё Combat Patrol, изменения очков MFM
  и поиск `Ctrl+K` по всему этому.
- **Ростеры.** Конструктор с очками по актуальному MFM и проверкой ограничений. Списки можно
  импортировать из приложения GW и New Recruit, экспортировать, отправить ссылкой и напечатать.
- **Партия.** Трекер на пять раундов для Singles и Doubles. Он показывает, что делают с юнитом
  правила его ростера. Есть совместная игра на нескольких телефонах через лобби, трансляция счёта
  в OBS и статистика сыгранных партий.

## Это зонтичный репозиторий

**Кода здесь нет.** Здесь лежит оболочка рабочей области: документация о том, из чего состоит
проект, журналы задач (`journal/`) и повторяемые процедуры (`.claude/skills/`). Сам продукт живёт
в отдельных репозиториях. Их клонируют **внутрь этой папки**, а в `.gitignore` они занесены
намеренно. Это не сабмодули.

Так сделано сознательно. Фронт деплоится статикой в бакет, бэк — облачной функцией, и
версионируются они независимо. Данные и словарь вообще никем не импортируются. Сабмодули без
всякой пользы связали бы их версии друг с другом.

| Папка | Что это | Стек | Репозиторий |
|-------|---------|------|-------------|
| `wh11ed/` | **Фронтенд**, то есть весь продукт: правила, фракции, конструктор ростеров, трекер, PWA. Здесь ~99% работы | Vue 3, Vite, Vitest | [wh11ed](https://github.com/Joker1796/wh11ed) · MIT |
| `wh11ed-api/` | **Бэкенд**: вход, облачная копия партий, ростеров и отметок игрока, совместная партия на нескольких телефонах, трансляция для OBS, архив чейнджлога, баг-репорты. Без него работает всё, кроме этого | TypeScript, Hono, YDB, Yandex Cloud Functions | [wh11ed-api](https://github.com/Joker1796/wh11ed-api) · MIT |
| `wh40k-appdata/` | **Данные**: упорядоченная англоязычная копия правил из официального приложения GW. Источник правды при сверке правил | JSON + скрипты | приватный, см. ниже |
| `wh-glossary/` | **Справочник** перевода сообщества (34k пар EN→RU). Не библиотека, никем не импортируется | TSV + Python | приватный, см. ниже |
| `journal/` | **Журналы задач**: что в работе, что отложено и почему, что закрыто. Индекс — `journal/INDEX.md` | Markdown | этот репозиторий |
| `.claude/skills/` | **Процедуры**: обновление данных, разбор баг-репортов, анонс релиза и другие. Список — в [`CLAUDE.md`](CLAUDE.md) | Markdown | этот репозиторий |
| `sources/` | Исходники: PDF правил, кодексы, глоссарии. Сама папка под гитом, содержимое — нет | — | — |

## Сборка рабочей области

```bash
git clone https://github.com/Joker1796/wh-rules.ru.git && cd wh-rules.ru

git clone https://github.com/Joker1796/wh11ed.git
git clone https://github.com/Joker1796/wh11ed-api.git      # только если трогаешь сервер

cd wh11ed && npm install && npm run dev                    # http://localhost:5173
```

Этого достаточно. **Фронт собирается и запускается без бэкенда, данных, словаря и исходников.**
Правила, ростеры, трекер и PWA работают на клиенте, а данные лежат в репозитории фронта готовыми.

Без бэкенда не будет входа, облачной синхронизации и совместной партии. По умолчанию фронт ходит
на локальный API (`VITE_API_BASE_URL`, по умолчанию `http://localhost:8787`). В dev-сборке в меню ⚙
есть тестовый вход без настоящего OAuth. Совместную партию на нескольких «телефонах» проверяют на
docker-стенде API (`npm run stand` в `wh11ed-api`, подробности в его README).

`wh40k-appdata/`, `wh-glossary/` и `sources/` нужны только для сверки правил и для повторного
извлечения текстов и картинок. На сборку они не влияют, см. [`sources/README.md`](sources/README.md).

```bash
cd wh11ed
npm run dev      # дев-сервер
npm test         # Vitest
npm run lint     # ESLint, гейт
npm run build    # прод-сборка в dist/
```

## Что открыто, а что нет

Открыты **`wh11ed` и `wh11ed-api`**. Оба под MIT, оба принимают PR.

**`wh40k-appdata` — приватный.** Это выжимка правил из официального приложения Games Workshop. Мы
держим её для сверки и перевода. Тексты, имена и характеристики — копирайт GW, публиковать их мы
не будем. Фронт от этого репозитория не зависит: данные попадают в него готовыми файлами.

**`wh-glossary` — приватный.** Это машинная выжимка из глоссария, который годами собирало
русскоязычное сообщество переводчиков. Без согласия авторов мы его не выложим. Ни фронт, ни бэк от
него не зависят: это справочник для работы над переводом.

Тексты правил Warhammer 40,000 принадлежат Games Workshop. MIT покрывает **код** проекта, а не
игровые тексты и не содержимое `sources/`.

## Куда смотреть под задачу

- **Правила, тексты, переводы EN/RU, вёрстка** → `wh11ed/src/data/`, `wh11ed/src/views/`,
  `wh11ed/src/components/`. Сначала прочитать `wh11ed/CLAUDE.md`, это карта фронта.
- **Конструктор ростеров, очки, импорт и экспорт** → `wh11ed/src/components/roster/`.
- **Трекер партии, совместная игра, статистика** → `wh11ed/src/components/tracker/` и
  `wh11ed/src/composables/useTracker.js`, `useParty.js`.
- **PWA, офлайн, деплой фронта** → `wh11ed/DEPLOY.md`.
- **Обновление правил из нового релиза приложения GW** → `wh11ed/DATA-SYNC.md`.
- **Вход, синхронизация, серверные ошибки** → `wh11ed-api/`, HTTP-контракт — в его `README.md`.
- **Сверить правило, характеристику или очки с первоисточником** → `wh40k-appdata/` (правила) и
  MFM (очки).
- **Не уверен, фронт это или бэк** → почти всегда фронт.

У крупных частей фронта свой `CLAUDE.md` в их директории (`src/data/`, `components/roster/`,
`components/tracker/`, `views/faction/` и другие). Это и есть подробная документация. Здешний
[`CLAUDE.md`](CLAUDE.md) — только маршрутизация, список процедур и стиль работы.

## Связи между проектами

`wh11ed` и `wh11ed-api` связаны **контрактом**. На бэке `src/domain/` проверяет конверты
сохранённой партии (`game.ts`) и ростера (`roster.ts`). Совместная партия ходит по частям, нарезанным
на фронте (`gameSlices.js`). Меняешь формат партии, ростера или вход на одной стороне — проверь
другую. Порядок выката при смене схемы описан в `wh11ed-api/README.md`: схема, функция, потом фронт.

`wh40k-appdata` и `wh-glossary` кодом ни с чем не связаны. Из первого данные переносят во фронт
скриптами сверки, второй — просто справочник для переводчика.

## Как включиться

Помочь можно с двумя вещами:

- **Данные и перевод.** Основная масса проекта и основной риск — двуязычные файлы правил. Самый
  частый баг здесь — рассинхрон EN и RU, а не ошибка в логике. Правки текстов и переводов
  приветствуются. Конвенции описаны в `wh11ed/src/data/CLAUDE.md`.
- **Код.** Во фронте много скрытой инфраструктуры: PWA, офлайн-загрузка, кэши. Её легко сломать
  незаметно. Поэтому в `CLAUDE.md` записаны инварианты «не чини это». Перед оптимизацией стоит
  проверить, нет ли на неё явного запрета.

Как это сделать: форкни репозиторий, заведи ветку и открой PR. Перед PR прогони `npm run lint`,
`npm test` и `npm run build`. Кроме тестов, во фронте есть гейты, например `npm run parity`
(баланс EN↔RU), `npm run radii` и `npm run dupes` (единый CSS), `npm run a11y` (контраст и
вёрстка). Их полный список — в `wh11ed/CLAUDE.md`. Вопросы и предложения — через issues.
