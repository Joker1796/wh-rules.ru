# WH Rules

Двуязычное (EN/RU) приложение для игры в **Warhammer 40,000, 11-я редакция**: посмотреть правило,
собрать ростер, отыграть партию — с правилами этого самого списка, применёнными к юнитам на экране.
Начиналось как поисковая замена листанию PDF за столом, и справочник остаётся фундаментом;
конструктор ростеров и трекер партии выросли поверх. Работает как обычный сайт и ставится как PWA —
установленное приложение после однократного прогрева работает полностью офлайн, за столом и без
сети. **Аккаунт не нужен ни для чего**, вход добавляет только синхронизацию между устройствами.

🌐 **[wh-rules.ru](https://wh-rules.ru)**

> отдаёт 301 сюда; всё новое катится только на `wh-rules.ru`.

## Это зонтичный репозиторий

**Здесь нет кода.** Репозиторий хранит только оболочку рабочей области: документацию о том,
из чего состоит проект и как его собрать. Сам продукт живёт в отдельных репозиториях, которые
клонируются **внутрь этой папки** и намеренно занесены в `.gitignore` — вложенными
репозиториями или сабмодулями они не являются.

Так сделано сознательно: проекты деплоятся и версионируются независимо (фронт — статикой в
бакет, бэк — облачной функцией), а данные и словарь вообще никем не импортируются. Сабмодули
связали бы их версии друг с другом без всякой пользы.

| Папка | Что это | Стек | Репозиторий |
|-------|---------|------|-------------|
| `wh11ed/` | **Фронтенд** — Vue 3 SPA: правила, Event Companion, фракции, конструктор ростеров, трекер партии, PWA. Здесь ~99% работы | Vue 3, Vite, Vitest | [wh11ed](https://github.com/Joker1796/wh11ed) · MIT |
| `wh11ed-api/` | **Бэкенд** — микросервис облачного бэкапа истории трекера и ростеров. Нужен только для входа и синхронизации; без него всё остальное работает | TypeScript, Hono, YDB, Yandex Cloud Functions | [wh11ed-api](https://github.com/Joker1796/wh11ed-api) · MIT |
| `wh40k-appdata/` | **Данные** — упорядоченная англоязычная копия правил из официального приложения GW: источник правды при сверке правил и точек | JSON + скрипты | приватный — см. ниже |
| `wh-glossary/` | **Справочник** перевода сообщества (34k пар EN→RU). Не библиотека, никем не импортируется | TSV + Python | приватный — см. ниже |
| `sources/` | Исходники: PDF правил, кодексы, глоссарии. Папка под гитом, содержимое — нет | — | — |

## Сборка рабочей области

```bash
git clone https://github.com/Joker1796/wh-rules.ru.git && cd wh-rules.ru

git clone https://github.com/Joker1796/wh11ed.git
git clone https://github.com/Joker1796/wh11ed-api.git      # только если трогаешь синхронизацию

cd wh11ed && npm install && npm run dev                    # http://localhost:5173
```

Этого достаточно: **фронт собирается и запускается без бэкенда, без данных, без словаря и без
исходников.** Правила, ростеры, трекер и PWA — всё клиентское, данные лежат в репозитории фронта
уже готовыми. Недоступны будут только вход и облачный бэкап: по умолчанию фронт смотрит на
локальный API (`VITE_API_BASE_URL`, по умолчанию `http://localhost:8787`), так что без запущенного
`wh11ed-api` попытка входа просто не пройдёт. Чтобы посмотреть UI залогиненного пользователя без
настоящего OAuth, в dev-сборке есть мок (`useAuth.js`, флаг `wh11ed-dev-mock-auth`; в прод-сборку
Vite его не включает).

`wh40k-appdata/`, `wh-glossary/` и `sources/` нужны только для сверки правил и повторного
извлечения текстов и картинок — на сборку они не влияют, см. [`sources/README.md`](sources/README.md).

```bash
cd wh11ed
npm run dev      # дев-сервер
npm test         # Vitest
npm run build    # прод-сборка в dist/
```

## Что открыто, а что нет

Открыты **`wh11ed` и `wh11ed-api`** — оба под MIT, оба принимают PR.

**`wh40k-appdata` — приватный.** Это выжимка правил из официального приложения Games Workshop,
которую мы держим для сверки и перевода. Тексты, имена и характеристики — копирайт GW; публиковать
их мы не будем. Фронт от репозитория не зависит: данные попадают в него готовыми файлами, так что
его отсутствие ничего не ломает.

**`wh-glossary` — приватный.** Это машинная выжимка из чужого документа: глоссария, который
годами собирало русскоязычное сообщество переводчиков. Выкладывать его в общий доступ без
согласия авторов мы не будем; вопрос об открытии открыт до получения апрува. Ни фронт, ни бэк
от него не зависят — это справочник для работы над переводом, а не часть сборки.

Отдельно: тексты правил Warhammer 40,000 принадлежат Games Workshop. MIT покрывает **код**
этого проекта, а не игровые тексты и не содержимое `sources/`.

## Куда смотреть под задачу

- **Правила, тексты, переводы EN/RU, вёрстка** → `wh11ed/src/data/`, `wh11ed/src/views/`.
  Первым делом прочитать `wh11ed/CLAUDE.md` — там про пайплайн data→view и двуязычные конвенции.
- **Конструктор ростеров, цены, ограничения детачмента, импорт/экспорт списков** →
  `wh11ed/src/components/roster/` (свой `CLAUDE.md` рядом).
- **Трекер партии, очки, миссии, стратагемы** → `wh11ed/src/composables/useTracker.js` +
  `wh11ed/src/components/tracker/`.
- **PWA, офлайн, деплой фронта** → разделы PWA / Deployment в `wh11ed/CLAUDE.md`.
- **Логин, облачный бэкап партий и ростеров, серверные ошибки** → `wh11ed-api/`
  (HTTP-контракт — в его `README.md`).
- **Сверить правило, характеристику или очки с первоисточником** → `wh40k-appdata/`.
- **Не уверен, фронт это или бэк** → почти всегда фронт.

Крупные фичи несут свой `CLAUDE.md` в собственной директории (`components/roster/`,
`components/tracker/`, `views/faction/` и другие) — он и есть подробная документация. В этой папке
[`CLAUDE.md`](CLAUDE.md) — только маршрутизация и стиль работы.

## Связи между проектами

- `wh11ed` ↔ `wh11ed-api` связаны **контрактом**: `src/domain/game.ts` и `src/domain/roster.ts`
  на бэке валидируют конверты сохранённой партии и сохранённого ростера. Меняя их формат или
  auth-флоу на фронте — проверь бэк, и наоборот. Это единственное место реальной сцепки.
- `wh40k-appdata` и `wh-glossary` кодом ни с чем не связаны: из первого данные переносятся в
  фронт скриптами сверки, второй — просто справочник для переводчика.

## Как включиться

Проект держится на двух вещах, и помочь можно с любой:

- **Данные и перевод.** Основная масса и основной риск — двуязычные data-файлы правил.
  Самые частые баги здесь не логические, а рассинхрон EN↔RU. Правки текстов, переводов и
  глоссов приветствуются; конвенции описаны в `wh11ed/CLAUDE.md` (раздел Bilingual content).
- **Код.** Фронт несёт много «скрытой» инфраструктуры (PWA, офлайн-прогрев, resume-view,
  кэш-стратегии) — её легко сломать незаметно, поэтому в `CLAUDE.md` подпроектов
  задокументированы инварианты «не чини это». Перед оптимизацией стоит проверить, нет ли на
  неё явного запрета.

Практически: форкни нужный репозиторий, заведи ветку, прогони `npm test` и `npm run build`,
открой PR. Помимо тестов есть guardrail-скрипты — `npm run parity` (баланс EN↔RU), `npm run radii`
и `npm run dupes` (единый стиль CSS); гонять их стоит как тесты. Линтера нет; следуй стилю
окружающего кода. Вопросы и предложения — через issues.
