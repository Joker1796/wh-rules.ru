# Каскад хэшей: релиз переименовывает файлы, которых не трогал

## Зачем

Владелец спросил, почему каждое обновление «перекачивает 700+ файлов». Ответ оказался из двух частей:

1. **Счётчик** докачки шёл по всему списку офлайн-файлов (463 кода + 314 картинок ≈ 777), хотя
   уже закэшированное service worker отдаёт из кэша. Исправлено сразу (wh11ed, `useOfflineWarmup.js`:
   считаются и качаются только файлы, которых нет в кэше; `DEPLOY.md` → warm-up).
2. **Каскад хэшей** — это и есть эта задача. Прод 2.7.13 → `main` 2.7.14: изменилось 116 файлов
   кода (2,02 МБ из 16,8 МБ), из них **68 файлов / 0,78 МБ (~40%) — только каскад**: в файле
   поменялась ровно одна строка, имя импортируемого общего чанка `app-<хэш>.js`
   (пример — `NotFoundView`: `from"./app-CsZA7mAe.js"` → `from"./app-D4FUUYA8.js"`). В `app`
   лежат модули, меняющиеся почти каждый релиз (`ui.js` и др.), его хэш меняется, а вслед за ним —
   каждый импортирующий его чанк. Картинки не затронуты (0 из 314).

Как мерили (повторить перед началом): скачать `https://wh-rules.ru/offline-manifest.json`,
собрать `main`, сравнить списки `assets.files`; для изменившихся сравнить тексты прод/новый после
замены всех `-<8 символов>.js|css` на `-H` — совпали → каскад.

## Варианты

- **import map** (`chunkImportMap` в Rolldown 1.2.8 — опция в нашей версии есть, семантику не
  проверяли: чтение `node_modules` в той сессии запретили). Чанки ссылаются по стабильным именам,
  хэши — в одной таблице на странице. Риски: import maps — Safari ≥16.4 (наш пол — Safari 16);
  затрагивает загрузку кода в PWA (precache оболочки, `navigateFallback`) и на SEO-страницах
  `seo-html/`; нужна проверка на iOS/Android и в установленном PWA.
- **Вынести самые изменчивые модули из `app`** (advancedChunks в `vite.config.js`, группа `app`)
  в свой чанк — сократит, но не уберёт: `ui.js` импортирует почти всё.
- Измерить на нескольких прошлых релизах, а не на одном, прежде чем выбирать.
