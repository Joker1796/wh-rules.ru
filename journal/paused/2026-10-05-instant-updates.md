# Обновления быстрее (особенно на десктопе)

Вопрос владельца: можно ли, чтобы десктоп получал обновлённые страницы моментально, или это
заблокировано архитектурой. **Не заблокировано** — телефон и десктоп сейчас обновляются
одинаково по настройке, а не по ограничению.

## Как сейчас (wh11ed `DEPLOY.md` «Updates», `src/components/UpdateToast.vue`)

Задержек две:

1. **Открытая вкладка** проверяет обновление раз в 15 минут (`UPDATE_CHECK_MS`), при возврате на
   вкладку и при переходах (не чаще раза в 2 минуты). Нашла — качает новую оболочку (~0.9 МБ) и
   сама перезагружается. Худший случай для простаивающей вкладки — 15 минут.
2. **Новый заход**: service worker сначала отдаёт старый `index.html` из precache, потом находит
   новую версию и перезагружает. Человек видит старую версию, а через пару секунд — перезагрузку.
   Скорее всего, ощущение «обновления не доходят» отсюда.

Плюс обновление в принципе доступно только после конца деплоя (сброс CDN — последний шаг).

## Варианты

- **А. Проверять чаще** — раз в минуту, пока вкладка видима. Проверка = условный GET `sw.js`
  (304, сотни байт). Худший случай 15 → ~1 мин. Вторую задержку не лечит.
- **Б. Навигация network-first с таймаутом** — `index.html` из сети, при отсутствии/медленной
  сети (таймаут ~1–2 с) — из precache. Новый заход сразу свежий, без перезагрузки. Precache не
  растёт, офлайн жив. Цена — на плохой связи открытие ждёт таймаут.
- **В. Сервер сам сообщает о версии** (WebSocket/SSE/Web Push) — Cloud Functions соединение не
  держат, нужен отдельный сервис ради выигрыша <1 мин против А. Не советую.

**Рекомендация:** А + Б для вкладки браузера (десктоп и телефон в браузере); установленное
приложение оставить как есть — там важнее быстрое открытие на плохой связи.

## Нюансы

- Service worker не знает, телефон это или десктоп: делить можно по ширине из страницы
  (сообщением в SW) или по «вкладка / установленное» (`isStandaloneDisplay()`).
- Автоперезагрузка раз в минуту может прилететь посреди чтения (она и сейчас автоматическая).
- Не возвращать отложенное по маршруту применение обновления — запрет в `DEPLOY.md`.
