# Данные к приложению GW: разбор sync-baseline, конец наследия Wahapedia

> **Статус:** активен — план, ждёт одобрения владельца
> **Репозитории:** wh11ed (данные, `scripts/sync-*.mjs`, `scripts/lib/sync-baseline.json`,
> `scripts/lib/appdata-exceptions.mjs`)
> **Начато:** 2026-10-03
> **Связано:** [2.7.13](2026-10-03-roster-archive-and-limits.md)

## Зачем

Датащиты пришли из импорта Wahapedia (wh11ed `5945a682`, 2026-07-09). `npm run sync` с первого дня
показывал, где они расходятся с приложением, но 2026-09-12 (`a13a6071`) завели
`sync-baseline.json`, чтобы отчёт показывал только новое, — и туда разом, **без причин**, легли все
732 тогдашние находки. С тех пор sync о них молчит. Так прожили до октября M `20+"` у самолётов
(нашлось только сверкой эрраты 2026-10-03, wh11ed `2fec4e49`).

Канон (решение владельца 2026-10-03): **приложение GW — последнее слово; эррата приложения выше его
таблиц и любого Faction Pack; очки — MFM.** Значит, каждая строка baseline — это либо наш дрейф,
либо осознанное расхождение, либо шум сравнения. Безымянных быть не должно.

## Новый стандарт — у каждого расхождения ровно один дом

1. **Исправлено по приложению** — строка уходит из baseline сама.
2. **Реестр исключений** (`appdata-exceptions.mjs`, гейт `npm run exceptions`) — мы сознательно
   расходимся с таблицами приложения (эррата, которую они не впитали; явная опечатка вроде AP «1»).
   С `why` и `source`; гейт следит за обеими сторонами.
3. **Правило сравнения** в самом sync — разница в записи, а не в правиле (наше «N/A» в BS, объединённые
   одинаковые профили). Нормализация в скрипте с комментарием и тестом, а не тысяча строк baseline.
4. **Baseline с причиной** — наш контент, которого в приложении нет по определению (Legends из
   Faction Pack'ов, своя проза Event Companion). Причина — непустая строка, одна на класс.

**Гейт в конце:** `npm run sync` падает на строке baseline без причины; `--baseline` не записывает
новую строку без причины. Пока идёт разбор — храповик: число безымянных только уменьшается.

## План

**Фаза 0 — инструмент и храповик (до правок данных).**
- Скрипт-категоризатор baseline: класс → число → список; печатает для строки «у нас / в приложении»
  рядом, чтобы решать пачками.
- Храповик в `npm run sync`: число строк без причины не растёт.
- Аудит покрытия sync: какие поля наших датащитов он не сравнивает вовсе. Пример пробела: Seraptek
  держал Super-heavy Walker в способностях фракции, а не core, и sync этого не видел.

**Фаза 1 — шум сравнения (данные не трогаем).** BS N/A, объединённые профили, двойной профиль
Chainfist, оговорка Judiciar, регистр заголовков и разметка в текстах базовых правил, очки → `sync:mfm`.
Цель — убрать сотни строк правилами сравнения с тестом на каждое.

**Фаза 2 — характеристики.** AP → реестр (новый вид записи `weapon-stat`), C'TAN POWER убрать,
Cadian 28mm, остальное поштучно. После неё в baseline нет ни одной строки про числа.

**Фаза 3 — тексты датащитов.** Правила, состав, способности, опции, Leader. Каждый дифф глазами:
по приложению, либо в реестр со ссылкой на эррату.

**Фаза 4 — фракции.** Правила армии, улучшения, стратагемы, лишние/отсутствующие детачменты.

**Фаза 5 — базовые правила и Event Companion.** То, что осталось после нормализатора.

**Фаза 6 — закрытие.** Гейт «без причины — нельзя», текст в `wh11ed/DATA-SYNC.md` §3 и
`src/data/CLAUDE.md`, урок в `APPDATA-SYNC-LESSONS.md` (принятый разом baseline = выключенный гейт).

Каждая фаза — свой коммит (или несколько), `npm run sync` + `data-gates` зелёные после каждой.
RU идёт вместе с EN: правка текста правила = правка обоих, `npm run parity`.

## Решения владельца (2026-10-03)

- **BS у оружия с автопопаданием — «-», как в приложении.** Данные переписать с «N/A» на «-»
  (224 строки baseline уйдут правкой данных, а не правилом сравнения).
- **Профили отрядов — храним как в приложении** (каждая модель своим профилем), **выводим
  схлопнуто чисто визуально**: одинаковые строки объединяет отрисовка, не данные.

## Проверено по вопросам 3 и 4 (2026-10-03)

- **Шесть детачментов SM «нет в приложении» — есть.** Blade of Ultramar, Shadowmark Talon,
  Ceramite Sentinels, Forgefather's Seekers, Medusa's Wrath, Spearpoint Task Force лежат в бандлах
  орденов appdata (`ultramarines`, `raven-guard`, `imperial-fists`, `salamanders`, `iron-hands`,
  `white-scars`), а sync сравнивает `space-marines.js` только с `adeptus-astartes.json`. Пробел
  сравнения: **их тексты не сверялись ни разу.** Ручная сверка 2026-10-03: стратагемы и улучшения
  совпадают (разница — разметка), одно настоящее расхождение — у нас «Stormseers' Wisdom», в
  приложении «Stormseer's Wisdom». → фаза 0: sync сравнивает детачменты SM и с бандлами орденов.
- **Deathwatch Support** лежит в `deathwatch.json`; по `detachment_faction_keyword` приложение даёт
  его Adeptus Astartes и всем орденам. У нас в конструкторе он есть у BT/BA/DA/SW
  (`sharedDetachments`), **у обычных Space Marines — нет** (`roster/space-marines.js`). Похоже на
  пробел конструктора — проверить в Battle Forge и чинить отдельно.
- **The Red Terror «Serpentine Fiend», Thulia Ghuld «Cybernetic Augmentation» — наследие Wahapedia.**
  Строки способностей в `tables/datasheet_ability.json` есть (текст «может проходить сквозь
  terrain…»), но ни в одной версии с 895 они не привязаны к датащитам
  (`datasheet_datasheet_ability`). На листе приложения их нет → убрать (EN+RU).
