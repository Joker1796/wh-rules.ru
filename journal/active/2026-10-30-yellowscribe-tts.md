# Экспорт ростера в Tabletop Simulator через Yellowscribe

## Откуда

Комментарий игрока в ВК 30.10 (Степа Рожков): «не хватает Yellowscribe или импорт в ттс».
Yellowscribe — сайт: грузишь ростер-файл → получаешь код → вставляешь в мод в TTS, и модели на
столе получают профили, оружие, способности.

## Что выяснили (30.10)

- Проект живой: <https://github.com/ThePants999/Yellowscribe>, последние коммиты 19.07 и
  02.08.2026, 11-я редакция уже поддержана (колонка InSv). Лицензия CC0.
- Принимает **только файлы**: `.ros`/`.rosz` (BattleScribe / New Recruit) и `.regiztry`
  (Rosterizer). Текст GW-приложения не понимает. Открытого API нет.
- **Каталоги BSData не нужны.** Разборщик (`bin/roszParser.js`) проверяет один постоянный
  `roster@gameSystemId` (`sys-352e-adc2-7639-d610` = 11e, `…-d6a9` = 10e), дальше читает только
  имена и форму:
  - `force > selections > selection[type=unit|model]` — юнит;
  - профиль `typeName="Unit"`: характеристики `M T SV W LD OC INSV`;
  - `Ranged Weapons` / `Melee Weapons`: `Range A BS|WS S AP D Keywords`; префикс `➤ ` у
    профилей мульти-оружия срезается;
  - `Abilities` (текст — первая характеристика), `rules > rule > description`;
  - `categories > category@name`, фракционные — с префиксом `Faction: `;
  - вложенные `selection[type=model]` / `upgrade`; `from="group"` = на все модели.
  - **Ловушка:** число у оружия делится на `number` модели (у BattleScribe X моделей с Y
    оружием = X·Y).
- Отсюда меняется старое решение. Раньше «`.ros/.rosz` не делаем» — речь шла про полноценный
  файл BattleScribe с id каталогов, под организаторов. Для Yellowscribe хватает урезанного
  `.ros` того же вида, а все данные у нас есть.

## План

1. **Проверка на живом сервисе.** Вручную собрать минимальный `.ros` (одиночная модель, отряд со
   сменным оружием, персонаж) → загрузить на yellowscribe.xyz → код выдан → проверить в TTS.
   Загрузку делаем только по «да» владельца. TTS есть у владельца или у игрока.
2. **`rosterToRos()`** в `wh11ed/src/core/roster/` рядом с `rosterExport.js`: ростер + данные
   фракции → XML без зависимостей. Только EN: Yellowscribe/TTS англоязычные, и наше правило
   «названия и keywords — по-английски» с этим совпадает. Снаряжение по моделям умножать по
   правилу BattleScribe. Прикреплённый персонаж — отдельный юнит. Модификаторы правил армии не
   переносим, только датащиты.
3. **Кнопка в `RosterExportModal`:** «Скачать файл для Yellowscribe (TTS)» под текстом
   + подсказка в два шага. Это файл, не седьмой текстовый формат.
4. **Гейты:** эталонный `.ros` на 9 тестовых ростерах (golden). Тест, который прогоняет наш XML
   через копию логики их разборщика: у каждой модели есть профиль и оружие.
5. Чейнджлог, бета → сайт, ответ игроку в ВК.

**Не делаем:** не отправляем на их сервер напрямую (чужой сервис без API), не пишем свой TTS-мод,
не делаем полноценный `.rosz` для BattleScribe/New Recruit.

## Ход работы

**30.10, шаг 1.** Запускать код Yellowscribe у себя нельзя: классификатор запретил исполнять
внешний код. Сверялся чтением `bin/roszParser.js` + `bin/10e11eDataModel.js`. Среди их
`samples/` нет ни одного файла 10e/11e, все 9e, так что форму 11e берём только из кода. Что
важно для генератора:

- `categories` у юнита обязательны: без них `parseUnit` падает на `categories[0]`.
- Одиночная модель — `selection[type=model]` прямо в `force > selections`. Свои профили и
  способности — в ней, оружие — во вложенных `upgrade`.
- Отряд — `selection[type=unit]`, в нём стеки `selection[type=model] number=N`, оружие стека —
  вложенные `upgrade` с `number = N × на модель`.
- Способность снаряжения (Relic Shield) — профиль `Abilities` во вложенном `upgrade` модели.
- Rosz-ветка не ставит ключевые слова Core/Faction, поэтому `rules` попадают в TTS обычными
  способностями. Текст правила брать из наших core/faction-правил (в проверочном файле
  вместо текста стоит имя).
- Ключевые слова оружия, которых нет в их словаре коротких имён (CLOSE-QUARTERS и др.),
  уходят строкой «имя: описание» с пустым описанием — косметика, смотреть по ответу сервиса.
- Если у модели два оружия с одним именем, но одно ближнее, а другое дальнее, разборщик сам
  дописывает к ним `(melee)` / `(ranged)`.

Pistol и Power Fist. Генератор — одноразовый скрипт в scratchpad, в репозиторий не идёт; код —
