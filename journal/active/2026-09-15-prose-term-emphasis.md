# Выделение игровых терминов прозы (класс C)

## Решение 2026-09-30: всплывашки терминов у всех фракций

Владелец: «сделаем глоссы для всех фракций по аналогии со спейсмаринами». Выбор из двух
предложенных вариантов:
- **Как у GW.** Всплывашка только там, где appdata выделяет термин жирным. Вариант «везде, где
  встречается» отклонён.
- **Все фракции одним заходом, одним релизом.** Не «Orks и AM сначала».

Катить только по команде владельца. Остановились до начала кода: ни одного файла под это не
тронуто.

**Как это устроено у SM (v2.7.8).** `wh11ed/scripts/gloss-bold-terms.mjs` (`npm run gloss`)
находит `**термин**`, известный глоссарию, и делает из него `[gloss:id:label]`:
- EN и RU формы — таблицы `EN_PATTERNS`/`EXTRA_EN`/`RU_FORMS`;
- одна всплывашка на термин в пределах раздела `###`, повторы остаются просто жирными;
- `[core:…]` не трогается;
- правит только четыре файла фракции: `factions/`, `datasheets/`, их `ru/`;
- область — `GLOSS_SLUGS` (SM и 5 орденов); генераторы зовут `glossFaction` только для них;
- `npm run sync` гоняет `--check` и выводит ⚠, а не ошибку.

**Замеры 2026-09-30 (`--check` по фракции).**
- Жирный уже есть и ждёт всплывашек: Orks — 411 строк, AM — 28, Agents — 16, остальные ≤6.
- У большинства фракций жирного на терминах нет вообще: проза набрана руками, в
  `factions/necrons.js` — 1 спан `**`, у Tyranids — 9. SM и Orks сгенерированы из appdata, поэтому
  жирный у них есть.
- Сам глоссарий SM подходит и к ним, словарь терминов общий.

## План

1. **Вернуть жирный класса C, но только на термины, которые знает глоссарий.** Пары «наша строка ↔
   строка канона» уже строит гейт: `eachFactionTextPair` (`scripts/sync-faction-text.mjs`) в
   `scripts/check-emphasis.mjs`, класс C печатает `node scripts/check-emphasis.mjs --all`.
   - Для каждого `**спана**` канона, которого нет у нас, проверить, узнаёт ли его сопоставитель
     глоссария (`glossString`).
   - Узнаёт — обернуть это место в нашей EN-строке и форму из `RU_FORMS` в параллельной RU-строке.
   - RU-форма не нашлась — не трогать **ни одну** сторону (`parity` считает `**`) и записать в отчёт.
   - Датащиты — тем же образом: способности в `datasheets/<slug>.js` против appdata.
2. **Снять ограничение области.** `GLOSS_SLUGS` → все фракции. Поправить вызовы в
   `gen-datasheets.mjs`/`gen-faction-rules.mjs` и строку в `wh11ed/src/data/CLAUDE.md`
   («Another faction joins by…»).
3. **`npm run gloss`** по всем фракциям. Разметка по разделам сработает сама.
4. **Глоссарий.** `gloss --check` печатает частые невыделенные термины. На 2026-09-30 в топе:
   - `Designer’s Note:` и строки «This model is equipped with:» — это не термины;
   - `riled up` — **не переводится, решение владельца по Orks**;
   - «приказ»/Officer (AM), pulse jet move/roll (Orks), Wych Cult, Incursion/Strike Force/Onslaught.
   Какие фракционные термины заводить в `src/data/glossary.js` — **спросить владельца списком**, не
   решать самому (у SM так же решали «топ ~80»).
5. **Гейты:**
   - `parity` 0 ошибок;
   - `npm run emphasis` (счётчик класса C упадёт; базлайн не трогать без чтения диффа);
   - `npm run gloss -- --check` зелёный;
   - тесты (`scripts/gloss-bold-terms.test.js` + весь `npm test`), lint, build.
   - Байтовая сверка: вне разметки текст не изменился — как делал для SM: дифф против коммита
     до прохода, отличается только разметка.
6. Пункт в чейнджлог (скил `changelog-entry`), релиз — по команде.

**Грабли, известные по SM:**
- писать файлы литерал за литералом (токенизатор в `gloss-bold-terms.mjs`), а не заменой
  строк — дубли и шаблонные константы давали промахи и качели;
- пустая часть в «A**/**B» даёт `[gloss:x:]` — защита есть, не снимать;
- ссылка на правило внутри текста глоссария — только `Имя (NN.NN)`, без слов в скобках, иначе
  ссылка не рендерится.

## Как было до решения

Отложено сознательно, решением пользователя 2026-09-15, при разборе
[потери выделения](../archive/2026/2026-09-15-emphasis-drift.md). Не долг, который забыли, а цена, которую
решили не платить сейчас.

## Что это

`npm run emphasis` печатает это число каждым прогоном. На 2026-09-15:

- **~2100 терминов прозы** — «unengaged», «detection range», «selected to shoot», «Hit rolls»:
  канон их выделяет, мы нет;
- **~1463 keyword'а вне списка автоболда рендерера** — TERMINATOR, CHAPLAIN, CRYPTEK, JUMP PACK и
  подобные. Капс им вернуть можно, но жирного он не даст: `useRenderInline` бодрит только
  `CORE_KEYWORDS` + `FACTION_KEYWORDS`.

Конвенция говорит «бодрим там, где бодрит PDF», так что формально это расхождение. Но 3.5 тысячи
правок ради терминов прозы — цена, несопоставимая с выигрышем, и в `src/data/CLAUDE.md` это
записано как осознанное исключение, а не как хвост.

## Что знать, если возвращаться

- **Словарь keyword'ов гейта — не эталон.** Он собран из appdata: все спаны `<k>`, прогоны капсом,
  имена и keywords датащитов. Туда затесались не-keyword'ы вроде «HIT ROLLS» и «WOUND ROLLS» —
  appdata где-то пишет их капсом. Прежде чем поднимать капс по этому списку, словарь надо сузить до
  курируемого (`<k>` + `datasheet.keywords` + имена датащитов) — иначе проза получит капс там, где
  его быть не должно.
- **Промежуточная ступень, если полный проход слишком дорог:** гейтить keyword'ы из курируемого
  словаря (TERMINATOR, CHAPLAIN, CRYPTEK — реальные keywords), оставив термины прозы. Это заметно
  меньше 1463 и качественно однороднее.
- **Расширять гейт — одна строка** в `check-emphasis.mjs`: класс B определяется тем, лежит ли спан в
  `autoBold` или содержит его (`anchored`). Применялка прохода была разовой и в репозитории не
  лежит; её решения описаны в активном журнале («Чему научил прогон»).
- **Правка любого класса идёт EN и RU одной правкой** — `parity` роняет сборку на одностороннем
  капсе, и это правильно.
