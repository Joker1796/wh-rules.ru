# Свой сборщик ошибок вместо Sentry

## Зачем

Сейчас мы узнаём о падении сайта у игрока, только если он сам написал отчёт. Смоук, a11y и тесты
ходят в Chrome и по нашим сценариям; Safari на iPhone, старые вкладки после выката, редкие данные
ростеров — слепое пятно. Нужна автоматическая сводка ошибок JS у всех посетителей.

**Почему не Sentry** (решение владельца 2026-10-14 — сначала план своего): SDK 30–70 КБ в стартовый
чанк против «лёгкого сайта во вкладке»; данные уходят в американский сервис (IP, адреса страниц —
152-ФЗ и доверие); шум и лимиты бесплатного тарифа. Своё — ~1 КБ на клиенте, данные на нашем
сервере, без личных данных.

## Что уже есть и на чём строим

- `wh11ed/src/composables/useErrorLog.js` — ловит `error` и `unhandledrejection` с самого старта
  (`main.js`), держит последние 10 для баг-репорта. Сюда добавляется отправка.
- `wh11ed/src/composables/staleChunks.js` — сайт сам лечит сбой загрузки чанка перезагрузкой; такие
  ошибки считать отдельно, это не баг страницы.
- `wh11ed-api/src/routes/feedback.ts` — образец публичного маршрута: zod, лимит размера, троттлинг по IP,
  без обязательного входа. Таблицы — `migrations/`, CLI — `scripts/feedback-list.ts`, почта —
  `scripts/notify.ts`, расписание — cron на сервере (как `backup.sh`, `gw-watch.sh`).

## Архитектура

### 1. Клиент (wh11ed)

- В `useErrorLog` к буферу добавить **отправку**: отпечаток ошибки (текст без чисел/адресов + первая
  строка стека без номера колонки) — одна и та же ошибка уходит **один раз за сессию**; не больше
  **5 разных за загрузку страницы**.
- **Фильтр шума** до отправки: расширения браузера (`chrome-extension://`, `moz-extension://`,
  `safari-web-extension://`), `ResizeObserver loop…`, `Script error.` без стека, ошибки при
  `navigator.onLine === false`. Сбой загрузки чанка — отправлять с пометкой `chunk` (видеть частоту,
  но не путать с багом).
- **Отправка пачкой**: копить 3 секунды или до `pagehide`, затем `navigator.sendBeacon('/errors')`
  (переживает закрытие вкладки).
- **Только с согласия (владелец, 2026-10-14):** отправка **по умолчанию выключена**; включить может
  любой — переключатель «Отправлять отчёты об ошибках» (меню ⚙, позже — окно «Все настройки»).
  Пока выключено, ошибки только копятся в буфере для баг-репорта, как сейчас.
- **Предложение включить:** вошедшему в аккаунт, если отправка ещё не включена и предложение **в этом
  браузере** ещё не показывалось, — один раз показать спокойное окно «Помогите находить ошибки…» с
  кнопками «Включить» / «Не сейчас». Помнится в localStorage браузера. Показывать в спокойный момент:
  не посреди партии и не в редакторе ростера (например, на главной или в списке ростеров).
- **Что уходит:** версия сайта (`APP_VERSION`) и данных (981), бета или прод, путь страницы **без
  `?` и `#`** (в `#r=` лежит ростер), текст ошибки (до 500 знаков), стек (до 2000), `navigator.userAgent`,
  установленное приложение или вкладка, язык. **Не уходит:** id пользователя, токены, содержимое
  ростеров и партий.
- Вес: около 1 КБ в стартовом чанке (буфер уже там).

### 2. Сервер (wh11ed-api)

- **Бета и прод раздельно (владелец):** две таблицы — `client_errors` (прод) и `client_errors_beta`,
  отдельные сводки и отдельный сторож. Канал определяет клиент (`VITE_BETA`).
- Миграция `003_client_errors.sql`: таблица **агрегатов**, не событий —
  `client_errors(fingerprint, app_version, kind, first_seen, last_seen, count, sample jsonb,
  browsers jsonb, routes jsonb, resolved_in text null)`, ключ `(fingerprint, app_version)`.
  Каждый приход — `upsert`: `count+1`, `last_seen`, счётчики браузеров (семейство + ОС из UA,
  разбирается на сервере) и страниц. Тысяча одинаковых ошибок = одна строка.
- Маршрут `POST /errors`: публичный, zod, тело до 8 КБ, до 20 ошибок в пачке, троттлинг по IP
  (~30 за 10 минут, как у отзывов — в памяти). **IP не сохраняется.**
- Хранение: строки без новых случаев дольше 30 дней удаляет ночной cron (или `backup.sh`).

### 3. Карты исходников (чтобы стек читался)

- Сборка с `build.sourcemap: 'hidden'`: карты создаются, но в бандле на них нет ссылки.
- `deploy.sh`: `*.map` **не** заливать в публичный бакет; копировать по scp на сервер в
  `/opt/wh-rules/sourcemaps/<версия>/` (там же, где лежат ключи — не публично).
- Расшифровка стека — на сервере, в сводке (пакет `source-map` в образе API).

### 4. Сводка и тревога

- `scripts/errors-list.ts [отпечаток]` — как `feedback-list`: новые и растущие ошибки, расшифрованный
  стек, версии, браузеры, страницы. `scripts/errors-resolve.ts <отпечаток> <версия>` — пометить
  исправленной; вернулась в более поздней версии — снова открыта.
- **Письмо раз в день** (cron 09:00 МСК → `notify.ts`): только новое и выросшее за сутки; пустой день
  без письма.
- **Сторож релиза**: в первые 2 часа после выката новая ошибка текущей версии, повторившаяся у 3+
  посетителей, — письмо сразу.

### 5. Разбор

- Скил `feedback-triage` дополняется разделом «ошибки»: та же логика «механизм → корень → класс →
  гейт», исправление закрывается `errors-resolve`.
- Помощь (`/help`, раздел о данных): одна строка о том, что сайт отправляет текст ошибок без личных
  данных.

## Проверки

- Клиент: тесты отпечатка, фильтра шума, лимита на сессию, вычищения `?`/`#` из пути.
- API: тесты разбора тела, лимитов, upsert-агрегации; гейт `npm test` в wh11ed-api.
- Стенд (docker `npm run stand` + Vite): брошенная ошибка доходит до таблицы, сводка показывает
  расшифрованный стек.

## Порядок выката (схема → API → клиент)

1. wh11ed-api: миграция + маршрут + CLI → деплой API (скил `deploy-api`).
2. wh11ed: отправка + карты исходников в `deploy.sh` → сначала бета, через день-два прод.
3. Сервер: cron сводки и очистки; сторож релиза.

Оценка: этап 1 (клиент, маршрут, таблица, CLI) — день; этап 2 (карты исходников, письма) — полдня-день;
этап 3 (сторож, скил, помощь) — полдня.

## Решения владельца (2026-10-14)

1. Переключатель есть; **по умолчанию выключено**, включить может любой; вошедшему — одноразовое
   предложение включить в этом браузере, если ещё не включено и не предлагалось.
2. Хранение — 30 дней.
3. Сторож релиза — 3 посетителя за 2 часа.
4. Бета и прод — раздельно (две таблицы, две сводки).
5. Делаем сами.

Следствие п.1: ошибок будет меньше, чем при сборе со всех, — сводка показывает и число включивших
(без личных данных: счётчик сессий с включённой отправкой за день), чтобы было видно, сколько
посетителей вообще «смотрят».
