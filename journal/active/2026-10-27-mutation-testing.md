# Мутационное тестирование (mutator)

Начато 27.10 по команде владельца («возьмём интересные инструменты и внедрим»), повод — навык
unclebob/ub-mode. Из трёх его инструментов взяли **mutator**: он портит код по одному месту
(`>=` → `>`, `??` → `||`, `1 - x` → `1 + x`) и смотрит, заметят ли тесты. crapper — на потом,
dryer не нужен (есть `npm run dupes`).

## Как устроено

- Клоны `tools/mutator`, `tools/crapper` в хабе (не в git, README «Сборка рабочей области»), Python 3.14.
- wh11ed: `npm run mutate -- <файл>` (`scripts/mutate.mjs`) — свои тесты файла, потом выжившие по
  `vitest related`; шум `?.` скрыт. `vitest.mutate.config.js` обязателен: без него мутатор врёт 100%
  (Vite уходит по симлинку из рабочей копии и падает на `test-setup.js`). Проверка честности —
  прогон с чужим тестом должен дать 0 убитых.
- wh11ed-api: `npm run mutate -- <файл>`; гоняет только тесты без базы.
- Нагрузка: 1 поток, `nice 19`, у node --test `--test-concurrency=1`. Владелец разрешил 2 процесса
  одновременно, не больше. 27.10 первый прогон бэка дал ~40 процессов node — остановлен, урок в памяти.
- Во время прогона **дерево не трогать**: воркеры — симлинки на настоящие файлы.
