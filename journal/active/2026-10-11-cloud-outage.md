статус-страница причину не называет).

Как пережил это фронт (прод v2.7.20, по коду): 502 без CORS-заголовков браузер видит как обрыв
сети. `useAuth.refresh()` в `catch` ставит `anon` — игрок выглядит вышедшим, но кука refresh
цела, после восстановления он снова войдёт сам. «Создать» совместную партию — неактивна с
«Войдите в аккаунт…», «Войти» уводит на голую 502 Яндекса. Гость по коду видит «Нет связи.».
Идущая совместная партия — «Нет связи — играем локально», после восстановления телефон шлёт
накопленную разницу, при конфликте по одной стороне побеждает сервер.

## Можно ли поднять бэк в соседней зоне — разбор

**Внутри Яндекса — нет такой ручки.** Всё наше — региональные serverless-сервисы: API Gateway,
Cloud Functions, YDB serverless, Lockbox, Certificate Manager. Зону у них не выбирают, отказоустойчивость
между зонами — обязанность Яндекса (YDB serverless по задумке держит копии в трёх зонах региона).
`zone = ru-central1-a` в `infra/variables.tf` — только дефолт провайдера Terraform, на эти ресурсы
не влияет. Раз лежит и функция, и база, и управление — это не «наша зона», а регион/управление;
переносить внутри ru-central1 некуда, да и нечем: `yc` не отвечает. ВМ в зоне d — тоже через
то же управление.

**Вне Яндекса — можно, но упирается в три вещи:**

1. **DNS тоже в Яндексе** (`NS ns1/ns2.yandexcloud.net`). Поменять запись `api.wh-rules.ru` во
   время сбоя управления нельзя. Выходы: сменить NS у регистратора на внешний DNS (переезд всей
   зоны, сайт тоже), или собрать фронт с другим адресом API (`VITE_API_BASE_URL` в
   `.env.deploy*`) на поддомене, который заранее живёт у другого DNS. Готовить заранее, не в сбой.
2. **Данные.** Своей копии базы нет — ни выгрузки, ни дампа. Запасной API поднимется только на
   пустой базе. Это терпимо: партии, ростеры и отметки живут на устройствах и зальются заново;
   пропадут очередь баг-репортов, идущие совместные партии и счёт аккаунтов.
3. **Код готов к переезду.** Вся логика за `app.fetch` (`src/app.ts`), Яндекс-специфичен только
   `adapters/yc-apigw.ts`; в Docker API уже работает на стенде (`docker-compose.yml`: node:22 +
   `local-ydb`, на x86-сервере без эмуляции). Нужно: адаптер/запуск под обычный Node-сервер в
   проде, секреты вне Lockbox, второй redirect URI у OAuth-приложений Яндекса и Google,
   cookie-домен (`siteForHost` в `src/config.ts` разрешит новый хост, если он в `ALLOWED_ORIGINS`).

**Деплой фронта во время сбоя возможен:** заливка идёт в Object Storage, он жив. Не сработают две
необязательные части `deploy.sh`: публикация заметок релиза в YDB (скрипт сам предупреждает и
оставляет их в файле) и сброс кэша CDN через `yc`. Последнее не страшно: `index.html` и `sw.js` лежат с `no-cache`, CDN это уважает (на главную `cache-status: MISS`), ассеты с хэшем в имени — новый выкат виден сразу; худший случай — запасной TTL ~600 с из `DEPLOY.md`, если режим CDN не «по заголовкам» (проверить, когда консоль вернётся). Дольше ждут сами клиенты — до 15 мин у открытой вкладки/PWA.

1. **Ежедневная выгрузка базы за пределы Яндекса.** Первое, как только облако поднимется.
   `ydb tools dump` (или export в S3) по расписанию → хранилище не у Яндекса. Проверить
   восстановление в `local-ydb` стенда — непроверенный бэкап не бэкап.
2. ~~Тексты фронта на «сервер недоступен»~~ — **сделано** (wh11ed `6b7b138b`, влито в `release/2.7.21` = `3ccc9484`, не выкачено, без записи в чейнджлог по решению владельца): состояние `down` в `useAuth` (повтор раз в минуту), «Войти» пингует `/health`, строки облака, совместная игра, вход по коду. **В бету не перенесено** — при вливании релиза в бету. Хвост: вкладка, открытая до сбоя, пишет «Не синхронизировано», а не «Сервер недоступен».
3. **Запасная площадка для API, записанная по шагам и один раз прогнанная**: где (VPS у другого

   выше), что с OAuth. Цель — поднять за час на последней выгрузке из п. 1.
4. **DNS вне Яндекса** — решить вместе с п. 3; пока зона у Яндекса, переключиться в сбой нельзя.
5. **Разобрать баг-репорты** — `feedback:list` не прошёл из-за сбоя.
6. **Проверить, что синхронизация догнала**, когда облако вернётся: вход сам, бэкап, совместная
   партия; логи функции за окно сбоя.
