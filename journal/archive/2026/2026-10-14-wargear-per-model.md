# Снаряжение по моделям: развести склеенные группы

## Откуда

Игрок: «Wracks — при добавлении более двух оружий Аколист вооружается двумя рукопашными, и это не
изменить». Разбор 2026-10-14 нашёл не один баг, а класс с одним корнем.

**Корень.** `mergeMiniatureDuplicates` (gen-roster-data.mjs) склеивает две копии одной инструкции —
на лидера и на рядовых, appdata пишет их по разу на миниатюру — в одну группу `all: 1` без `m`.
Склейка спасала от двойного лимита, но конструктор перестал знать, КАКАЯ модель взяла опцию.
Всё, что от этого зависит, повисло:

1. **Опция модели, меняющая предмет, который у неё бывает только из общей группы** — открыта всегда,
   ошибки нет: Wracks (Acothyst: torturer’s tool → power weapon), Desolation Squad (сержант:
   Superkrak → Vengor).
2. **«X или Y», где Y только из общей группы** — ложная ошибка перерасхода на законном списке:
   Einhyr Hearthguard (Hesyr → graviton hammer при plasma blade у всех), Hernkyn Yaegirs (magna-coil /
   APM при revolver+knife у всех).
3. **Лимит на каждую опцию** («For every 5 models: ◦ 1 hexrifle ◦ 1 liquifier…», appdata — четыре
   набора по одной опции) не пристёгивается к группе из четырёх опций (`linkWargearLimits` ищет набор,
   покрывающий группу целиком). Редактор держит «+» верно (читает прозу), валидатор и импорт — нет:
   2 hexrifle на 5 моделей проходят без ошибки.

Симптом игрока, вероятнее всего, п.1: вторая группа Acothyst всегда показывает отмеченный «Torturer’s
tool» рядом с «Twin torturer’s tools» — «два рукопашных», и снять это нельзя (это состояние, а не
выбор). Блокировку буквально не воспроизвели (5/6/10 моделей, оба порядка). «Статус с ошибкой» у
списка из одних Wracks — «нет Warlord».

## Как у GW (проверено в Battle Forge 2026-10-14, без входа)

Предметы на МОДЕЛИ, не варианты замены: блок Acothyst (галочки) и блок Wrack (степперы), инструкция
«For every 5 models» напечатана в обоих. Кнопки ничего не запрещают, проверка — потом, по отряду
(«Invalid wargear configuration for Wracks», без подробностей).
- Wracks ×5: hexrifle у Acothyst — ок; hexrifle у Acothyst + liquifier у Wrack — ок;
  hexrifle у Acothyst + hexrifle у Wrack — **invalid**. Лимит «1 каждого на 5» общий на отряд, Acothyst в нём.
- Hearthguard ×5: Hesyr с graviton hammer, четверо с plasma blade — ок (у нас ложная ошибка).
- Desolation / Yaegirs в приложении не гоняли: GW сверяет итоговые предметы, итог однозначен по тексту.

## Решения владельца (2026-10-14, сверено дважды)

- **Редактор раскладывается по профилям моделей.** Если в отряде больше одного вида моделей — у
  каждого профиля ОДИН блок: его уникальные опции и рядом его копия общей. Не «три группы»
  (уникальное сержанта / общее / рядовые) — общее просто попадает в блок сержанта. Игрок однозначно
  выбирает, КОМУ отдаёт опцию. Порядок блоков — сержант первым (как appdata/GW); профиль без опций
  блока не получает; одиночный профиль — галочки/радио, многомодельный — степперы.
- **Копия — только у тех профилей, которые реально могут взять.** Источник — appdata: инструкция
  записана на каждый профиль, которому доступна (Fortis Kill Team: 2 из 6 профилей; Wolf Scouts — без
  Hunting Wolf). Копий ровно столько, сколько записала appdata, без угадывания.
- **Лимит общий на все копии**; исчерпан другой копией — кнопка гаснет с причиной («взял Acothyst»),
  не прячется. **Руками переставить можно всегда.**
- Разводим **все** склеенные группы (92 в 57 юнитах), чиним весь класс.
- **Импорт:** указано, кто взял (GW-формат «1x Acothyst … hexrifle»), — тому профилю. Не указано, и
  миграция старых списков — одно правило: сначала сержанту / меньшей группе, остаток — большей.
- Карточка/печать/экспорт пишут оружие под тем профилем, кто взял (условность «большой профиль
  первым» уходит).
- Заодно: **наш экспорт → наш импорт** на разных ростерах (сейчас тест один — World Eaters).

## План

1. Генератор: не склеивать; копиям одной инструкции — общий пул лимита (новое поле, движок такого
   не умеет: `xpm` — это лимит на ОДНУ модель через группы, не на отряд). Лимиты «по одной на каждую
   опцию» собирать в лимит группы/пула (Wracks: 5–9 → 4 всего / 1 каждого; 10 → 8 / 2).
2. Движок: пул в `wargearGroupCap`/`swapRoom`/`stockBlocker`/`fitWargear`/валидаторе; запас по профилю.
3. Редактор: блоки по профилям (уникальные + копия общей), перестановка между копиями, причина
   у погашенной кнопки. До правки — снимки сложных юнитов (Kill Teams, Company Heroes, Corsair
   Voidscarred — 3+ профиля, у сержанта и свои, и общие опции).
4. Карточка/печать/экспорт: `splitBearers` — копии уже знают профиль, условность «большой профиль
   первым» уходит для них.
5. Импорт: профиль указан → ему; без профиля → сначала меньшей группе; `useRosters.js` SCHEMA bump — перенос
   старых `all`-пиков тем же правилом.
6. Гейты: (а) опция модели меняет/упоминает предмет из общей группы → должна знать, у кого он;
   (б) набор лимитов appdata по опциям без `lim` → красный; доказать красноту на старом коде.
   Тесты: 4 юнита + Wracks-лимит; round trip всех тестовых ростеров во всех форматах + свод по корпусу.
7. Урок в `APPDATA-SYNC-LESSONS.md`, `roster/CLAUDE.md` («One bullet, recorded once per miniature»
   переписать), чейнджлог 2.8.3 (ответ игроку), удалить репорт `a24c2b8a` после релиза.

Класс посчитан скриптами в scratchpad сессии (не в репо): все `all`-группы × опции профилей, чей
`rep` вне его defaults и есть в общей группе.

## Устройство (решено при разборе кода, 2026-10-14)

- **Склейка остаётся способом НАЙТИ копии и пристегнуть лимит** (`mergeMiniatureDuplicates` до
  `linkWargearLimits` — иначе набор лимита снова «неоднозначен»), а на выходе черновик с копиями
  разворачивается в группу на каждый профиль с настоящим `m`. Весь проверенный путь «группа профиля»
  в движке работает как есть.
- **Общий лимит — на отряде** (`u.pools = [{ g: [gi…], lim? }]`, сержант первым), не на группе:
  ограничение через несколько групп, как `xpm`. Каждая копия без `lim` → потолок «модели профиля × cp».
  Бюджет на модель («до 2, без дублей») — не пул, а поле копии.
- **Индексы стабильны**: копия сержанта встаёт на место склеенной группы, остальные — в конец `gear`.
  Старые выборы падают на сержанта; миграция v11 переливает лишнее остальным копиям по таблице от
  генератора (`migrateRoster` синхронный, данных фракции не видит). Бэкенд не трогаем: ростер для него
  непрозрачный JSON со своим `v`.
- «This unit can be equipped with…» (Watcher in the Dark, единственный случай) не разводится — блок «Отряд».
- 10 из 92 групп — из `pack-roster.mjs` (Legends), разводить и там.
