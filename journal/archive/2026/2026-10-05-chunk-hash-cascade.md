# Каскад хэшей: релиз переименовывает файлы, которых не трогал

## Зачем

Владелец спросил, почему каждое обновление «перекачивает 700+ файлов». Ответ оказался из двух частей:

1. **Счётчик** докачки шёл по всему списку офлайн-файлов (463 кода + 314 картинок ≈ 777), хотя
   уже закэшированное service worker отдаёт из кэша. Исправлено сразу (wh11ed, `useOfflineWarmup.js`:
   считаются и качаются только файлы, которых нет в кэше; `DEPLOY.md` → warm-up).
2. **Каскад хэшей** — это и есть эта задача. Прод 2.7.13 → `main` 2.7.14: изменилось 116 файлов
   кода (2,02 МБ из 16,8 МБ), из них **68 файлов / 0,78 МБ (~40%) — только каскад**: в файле
   поменялась ровно одна строка, имя импортируемого общего чанка `app-<хэш>.js`
   (пример — `NotFoundView`: `from"./app-CsZA7mAe.js"` → `from"./app-D4FUUYA8.js"`). В `app`
   лежат модули, меняющиеся почти каждый релиз (`ui.js` и др.), его хэш меняется, а вслед за ним —
   каждый импортирующий его чанк. Картинки не затронуты (0 из 314).

Как мерили (повторить перед началом): скачать `https://wh-rules.ru/offline-manifest.json`,
собрать `main`, сравнить списки `assets.files`; для изменившихся сравнить тексты прод/новый после
замены всех `-<8 символов>.js|css` на `-H` — совпали → каскад.

## Варианты

- **import map** (`chunkImportMap` в Rolldown 1.2.8 — опция в нашей версии есть, семантику не
  проверяли: чтение `node_modules` в той сессии запретили). Чанки ссылаются по стабильным именам,
  хэши — в одной таблице на странице. Риски: import maps — Safari ≥16.4 (наш пол — Safari 16);
  затрагивает загрузку кода в PWA (precache оболочки, `navigateFallback`) и на SEO-страницах
  `seo-html/`; нужна проверка на iOS/Android и в установленном PWA.
- **Вынести самые изменчивые модули из `app`** (advancedChunks в `vite.config.js`, группа `app`)
  в свой чанк — сократит, но не уберёт: `ui.js` импортирует почти всё.
- Измерить на нескольких прошлых релизах, а не на одном, прежде чем выбирать.

## Исследование import map (2026-10-05, кода в репозитории нет)

Пробник — отдельный конфиг поверх `vite.config.js` (`build.rolldownOptions.experimental =
{ chunkImportMap: { fileName: 'importmap.json' } }`, `outDir` в scratchpad), сборки релизов — в
git worktree с симлинком `node_modules`. Что выяснилось:

- **Механизм работает как обещано.** Чанки импортируют друг друга по стабильному ключу
  (`./app-C3oHh4_Z.js`), карта `importmap.json` ведёт ключ к настоящему файлу; ленивые `import()`
  роутера — тоже по ключам. Правка одной строки в `ui.js`: без карты переименовано **107** файлов,
  с картой — **1** (сам `app`).
- **Но Vite с ней теряет CSS ленивых страниц.** Списки предзагрузки `__vite__mapDeps([...])`
  становятся `[]`, а через них грузится CSS чанка. Проверено в браузере (playwright над preview,
  карта вписана в `index.html` руками): `/ru/roster` — 20 таблиц стилей без карты, **1** с картой;
  код работает, страница без стилей. Опция экспериментальная, Vite её не знает и карту в HTML сам
  не вставляет.
- **Реальная выгода на четырёх последних релизах** (новые файлы кода / КБ):

  | релиз | без карты | с картой |
  |---|---|---|
  | 2.7.10→2.7.11 | 156 / 6402 | 157 / 6556 |
  | 2.7.11→2.7.12 | 107 / 2679 | 43 / 2097 |
  | 2.7.12→2.7.13 | 239 / 10185 | 243 / 10369 |
  | 2.7.13→2.7.14 | 118 / 2599 | 65 / 2101 |

  Маленький релиз — минус ~50–60 файлов и ~0,5 МБ из ~2,6; крупный — ноль: там меняются сами
  данные фракций и `app` (в 2.7.12→2.7.13 впереди astra-militarum 731 КБ, app 615, space-marines
  534, combatPatrol 485), и минифицированные имена экспортов `app` перетасовываются — каскад
  возвращается и с картой. Всего кода ~16 МБ.

## Чего стоило бы довести

1. Свой плагин, возвращающий CSS-зависимости ленивых чанков (или `cssCodeSplit: false` — весь CSS
   одним файлом на старте вкладки, против принципа «лёгкая вкладка»).
2. Вставка карты во все HTML: `index.html`, 3141 страница `seo-html/`, `navigateFallback` SW.
3. Пол браузеров: import maps — Safari ≥16.4, у нас Safari 16 → полифил или поднять пол.
4. Проверка на iOS/Android во вкладке и в установленном PWA, переходы между версиями.
5. Экспериментальная опция Rolldown — может поменяться на любом бампе.
